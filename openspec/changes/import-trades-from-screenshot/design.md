## Context

目前買賣紀錄只能由 AddHistoryViewController 逐筆手動輸入，經 AddHistoryViewModel 的 saveNewInvestRecord 呼叫 NetworkServiceImpl 的 saveNewRecord，同時寫入本地 Core Data（InvestHistory）與 Firestore。InvestHistory 只有 stockNo、date、price、amount（單位為「股」，Core Data 型別為 Integer 16，LocalDBService 以 Int16(amount) 轉型）、status（0 買、1 賣）、reason 六個欄位。Firestore 刪除買賣紀錄時（OnlineDBService.deleteHistoryFromOnlineDB），只以 email 與毫秒時間戳查詢並刪除第一份文件。

使用者的實際交易在元大證券「投資先生」app。該 app 沒有匯出功能，也沒有第三方可用的 API，只能從「交易 → 明細」畫面取得資料。已取得的畫面樣本顯示：

- 每筆交易是上下兩行：上行為年份（`2026/`）、股名、價格、應收付；下行為月/日、買賣類型（`盤中零股買進` 或 `盤中零股賣出`）、股數、損益。
- 畫面只有股名，沒有股號，展開明細後也沒有。
- 點右側箭頭展開後，會多出一塊明細：委託書號、持有成本、價金、手續費、交易稅、配息總額、報酬率、幣別，以及「沖抵明細」按鈕。
- 畫面上方有總應收付、總損益、總價金、總手續費、總交易稅的摘要列，表頭列為日期、名稱、價格/股數、應收付/損益。

專案最低部署版本改為 iOS 18.0（App、小工具、Live Activity 與測試 target 一致）。Vision 的繁體中文辨識與 PHPickerViewController 都可直接使用。

本變更依賴 refresh-stock-list：股名對股號與手動輸入股號的驗證都讀取該變更提供的 StockListRepository。因此合併順序為 refresh-stock-list 先、本變更後。

## Goals / Non-Goals

**Goals:**

- 使用者選一張或多張投資先生明細截圖，經裝置端 OCR 與解析後，在預覽頁確認，再寫入既有買賣紀錄。
- 解析器只依賴「文字加座標」，不依賴 Vision，可用截圖樣本寫單元測試。
- 寫入路徑與手動輸入相同，Firestore 同步與 Android 跨平台行為不受影響。
- 辨識錯誤不會直接進入資料庫：預覽頁是必經步驟，且寫入前會先驗證所有勾選項目，避免部分寫入與 crash。
- 匯入完成後，首頁清單與小工具立即反映新加入的股票。

**Non-Goals:**

- 不支援其他券商、CSV、Excel、券商 API。
- 不支援現股（整股）、當沖、融資融券、定期定額（無樣本，現股的股數單位未確認）；這些筆在預覽頁標為不支援。
- 不儲存手續費與交易稅，不修改 Core Data 與 Firestore schema。
- 不使用委託書號去重。
- 不上傳截圖或辨識文字到任何伺服器。

## Decisions

### 使用 Vision 在裝置端辨識文字，並輸出文字加座標

採用 VNRecognizeTextRequest，recognitionLevel 設為 accurate，recognitionLanguages 設為 zh-Hant 與 en-US，usesLanguageCorrection 設為 false（語言校正會改動股名與數字）。辨識結果封裝成 RecognizedTextBox（文字、標準化座標，原點在左下，y 越大越靠上，與 Vision 一致），由 TradeTextRecognizer 提供；解析器不 import Vision。

替代方案：(a) 雲端 OCR 服務：需上傳個人交易畫面，有隱私疑慮且需要金鑰，捨棄。(b) 只取辨識出的文字行順序：版面是兩行欄位對齊，Vision 可能依欄位而非依列輸出，順序不可靠，捨棄。

### 使用 PHPickerViewController 選圖，辨識在背景執行

專案是 UIKit，選圖採用 PHPickerViewController（selectionLimit 設為 0 可多選）。它不需要相簿權限，因此不存在「相簿權限失敗」的情況，只有「載入圖片失敗」。VNImageRequestHandler.perform 是同步的重運算，必須在背景執行；辨識完成後回到 main thread 才更新預覽頁。

替代方案：SwiftUI 的 PhotosPicker：需要以 UIHostingController 包裝，在 UIKit 流程中沒有額外好處，捨棄。

### 依座標分群成一筆交易，不依文字行順序

解析器以「類型欄文字」作為每筆交易的錨點：文字（去除空白後）以「買進」或「賣出」結尾的文字框，視為下行的類型欄；若 Vision 把相鄰欄位合併成一個文字框（例如 `09/30 盤中零股買進`），以正規表示式分別取出月/日與類型。

「同一行」的判定以文字框高度為單位：兩個文字框的垂直中心距離不超過該行文字框高度中位數的 0.5 倍。上行必須同時符合：位於錨點上方（y 較大）、垂直距離在錨點文字框高度的 0.5 到 2.5 倍之間、含有符合 `^\d{4}/` 的年份片段與一個股名文字框。不符合時，該筆標為不完整，不從其他列借用內容。同一行內再依 x 座標歸欄：日期欄、名稱欄、價格/股數欄、應收付/損益欄。買賣方向只看文字，不看紅綠顏色。

摘要列與表頭列的標籤（總應收付、總損益、總價金、總手續費、總交易稅、日期、名稱、價格/股數、應收付/損益）與其同列的值不參與分群。

替代方案：以固定列高切割：不同手機截圖尺寸與縮放不同，列高不固定，捨棄。

### 展開區塊的文字一律忽略

當某一行文字包含 `委託書號`、`持有成本`、`價金`、`手續費`、`交易稅`、`配息總額`、`報酬率`、`幣別`、`沖抵明細` 其中之一，該行與其同列的值都不參與分群。這些標籤不會被當成交易錨點，因此收合與展開的截圖解析結果相同。

替代方案：解析展開區塊取得委託書號當去重鍵：收合畫面看不到，只能涵蓋部分截圖，捨棄。

### 以股名精確對照既有股票清單取得股號

新增 StockNameResolver，建構時注入股票清單條目（StockListEntry 陣列），正式環境由 StockListRepository 提供，測試則注入固定資料。比對前，清單名稱與 OCR 名稱都先做正規化：Unicode 相容正規化（全形轉半形）後移除所有空白字元（含全形空白）。正規化後做精確比對，不做模糊比對，避免誤判成別檔股票。正規化後同名對到多個股號，或對不上時，該筆標示為「股號未確定」，預覽頁標紅，使用者必須手動輸入股號才能勾選；輸入值必須與清單內某個代號完全相等（StockListRepository.contains(code:)），否則仍不可勾選。

替代方案：模糊比對或相似度排序：會把 OCR 錯字默默對成別檔股票，寫入錯誤資料，捨棄；改為讓使用者明確選擇。

### 股數單位為「股」，直接存入 amount

投資先生零股畫面的股數就是股（`5` 代表 5 股），既有 amount 欄位單位也是股（手續費公式為 price 乘 amount），因此不做單位轉換。amount 在 Core Data 是 Integer 16，有效範圍為 1 到 32767；超出範圍的股數在預覽頁標為不完整，不可勾選。

### 入口放在首頁「+」按鈕展開的選單

匯入的截圖會同時包含多檔股票，所以入口不能放在針對單一股票的 AddHistoryViewController。首頁右下角的「+」按鈕（FloatingButton）由 FloatingButtonManager 展開選單。本變更保留這個展開機制，並重新設計外觀：選項改為毛玻璃膠囊，左側是彩色圓形圖示（SF Symbols），標題在右；「+」展開時旋轉成「×」，選項依序彈出，背景加上模糊遮罩，點背景可收起。選單項目由近到遠為「新增清單」、「新增股票」（只在已有清單時出現）、「截圖匯入」，用垂直 UIStackView 排列，隱藏項目不留空隙，不再需要手動計算偏移。「截圖匯入」透過 FloatingButtonManagerDelegate 的 didTapSecondaryButton3 回呼，由 StockListViewModel 經 StockListCoordinator 開啟選圖與預覽頁，沒有任何清單時也可使用。

替代方案：(a) 股票清單頁導覽列的選單：與既有的新增入口分散，捨棄。(b) 設定頁：不易被發現，捨棄。(c) 第三方浮動按鈕套件（例如 Floaty、JJFloatingActionButton）：只為三個選項多一個相依，且多數已停止維護，捨棄。(d) iOS 系統彈出選單（UIButton 的 menu）：實作過，視覺上不符合需求，捨棄。

### 預覽頁為必經步驟，並在此完成去重

TradeImportViewModel 接收解析結果，產生預覽項目清單。每項有四種狀態，優先順序為：不支援、不完整、重複、可匯入（同時符合多種時，顯示優先順序較前者）。去重鍵為「股號、日期（以台北時區的日曆日為單位）、價格、股數、買賣方向」，比對對象為本地既有買賣紀錄，以及同一批預覽項目內較前面的項目。重複項預設不勾選，但使用者可手動勾回（因為同日同價同股數的兩次合法交易會被判為重複）。不完整項（缺股號、價格、股數或日期，或股數不在 1 到 32767、價格不大於 0）標紅且不可勾選，直到使用者補完。使用者編輯欄位後重新計算狀態：變成可匯入者自動勾選，變成重複或不完整者自動取消勾選。

替代方案：直接匯入並事後復原：寫入已同步到 Firestore，復原需要再刪除線上資料，捨棄。

### 匯入時可選擇加入的清單

InvestHistory 沒有清單欄位，買賣紀錄以股號查詢，與清單無關。因此「選擇清單」的意思是：把匯入的股票加入所選清單，讓使用者回到首頁就能在該清單看到這些股票。預覽頁頂部放清單選擇器，選項為 fetchAllListFromDB 取得的所有清單加上「不加入清單」，預設為首頁目前顯示的清單；沒有任何清單時，預設為「不加入清單」。

確認匯入時，對「實際匯入的交易」取不重複的股號，逐一呼叫既有的 NetworkServiceImpl.saveStockNumber（with: currentFollowingList:）。底層 LocalDBService.saveNewStockNumberToDB 已在清單內重複時不寫入；匯入層仍先排除已在所選清單中的股號，避免重複上傳 Firestore。這點必須守住，因為 1.19 曾因同一清單內出現重複股號而在啟動時崩潰。選「不加入清單」時，匯入的買賣紀錄只存在於資料庫，無法從首頁進入該股票的詳細頁看到，預覽頁在選擇器下方顯示一行提示說明這點。

替代方案：(a) 不處理清單：匯入的股票若不在任何清單，首頁看不到，使用者要自己再新增；(b) 每檔股票各自選清單：預覽頁太繁瑣，捨棄；(c) 把買賣紀錄綁到清單：需要改 schema，捨棄。

### 匯入紀錄的時間戳與日曆日規則

截圖只有年月日，沒有時分秒。Firestore 的買賣紀錄以 email 與毫秒時間戳識別，刪除時只刪第一份符合的文件，所以匯入紀錄的時間戳不能撞號。規則：匯入紀錄的基準時間為「台北時區（Asia/Taipei）當日 12:00:00.000」；批次內與本地既有買賣紀錄中，若該毫秒時間已被使用，就加 1 毫秒再檢查，直到不重複。所有「同一天」的判定（去重）都以台北時區的日曆日為準，與裝置時區無關。

### 寫入前先驗證全部勾選項目，且在主執行緒寫入

confirmImport 在寫入第一筆之前，先驗證所有勾選項目都合法（股號存在於清單、價格大於 0、股數 1 到 32767、日期存在）；只要有一筆不合法就不寫入任何資料並回傳錯誤。通過後，在 main actor 上逐筆呼叫 NetworkServiceImpl 的 saveNewRecord（LocalDBService 使用 viewContext，不能在背景執行緒寫入）。回傳值是「送出寫入的筆數」，因為 saveNewRecord 沒有回傳成功與否，儲存失敗時只會發出 dataSaveDidFail 通知。

### 預覽頁以 push 進入，匯入後通知首頁重新載入

預覽頁以 push 方式加入首頁所屬的 navigationController，不用 modal sheet（sheet 關閉時不會觸發首頁的 viewWillAppear）。匯入完成後，預覽頁呼叫 callback，由 StockListViewModel 重新載入目前清單，並更新 App Group 中的 stockNos 與重新載入小工具時間軸，就像手動新增股票後一樣。

### 寫入沿用 saveNewRecord，不新增寫入路徑

勾選的項目逐筆呼叫 NetworkServiceImpl 的 saveNewRecord（reason 一律傳空字串），因此本地與 Firestore 一致。不新增 Core Data 欄位或 Firestore 欄位。

### 手續費與交易稅只顯示、不儲存

第一版只讀取買賣方向、股名、價格、股數、日期。即使展開畫面有手續費與交易稅，也不寫入。

## Implementation Contract

**Behavior:**

- 點選首頁右下角的「+」按鈕會展開選單，其中有「截圖匯入」。點選後開啟系統照片選取器（可多選），逐張辨識，結果彙整進同一個預覽頁。
- 預覽頁頂部有「加入清單」選擇器，預設為首頁目前顯示的清單，可改選其他清單或「不加入清單」。
- 預覽頁逐筆顯示：勾選框、日期、股號與股名、買或賣、價格、股數，以及狀態（可匯入、重複、不完整、不支援）。使用者可編輯股號、價格、股數、日期、買賣方向。按下「匯入」才寫入勾選的項目，完成後回到首頁並顯示送出筆數。
- 沒有任何勾選項目時，「匯入」按鈕為停用狀態。
- 匯入完成回到首頁時，新加入的股票立即出現在首頁清單，小工具資料也已更新。

**Interface / data shape:**

- RecognizedTextBox：text（String）、boundingBox（CGRect，標準化座標，原點在左下，y 越大越靠上）。
- ParsedTrade：stockName（String）、date（Date?）、price（Float?）、amount（Int?）、side（買或賣）、tradeTypeText（String）、isSupportedType（Bool）。
- 支援的類型字串：盤中零股買進、盤中零股賣出、盤後零股買進、盤後零股賣出（股數欄以「股」計）。其他以「買進」或「賣出」結尾的類型字串（例如現股買進、融資買進、定期定額買進）會產生 isSupportedType 為 false 的 ParsedTrade。
- TradeScreenshotParser.parse(boxes: [RecognizedTextBox]) 回傳 [ParsedTrade]；純函式，無副作用。年份只取自上行的 `yyyy/` 片段，缺少時 date 為 nil。
- StockNameResolver(entries: [StockListEntry]).resolve(name: String) 回傳股號或 nil；對到多個股號時回傳 nil。
- TradeImportViewModel 提供：載入解析結果、切換勾選、編輯欄位、取得預覽項目（含狀態）、可選清單與目前選擇（selectedList）、confirmImport()（main actor，回傳送出筆數或驗證錯誤），並在寫入後把匯入股票加入 selectedList。

**Failure modes:**

- 截圖辨識不到任何交易：預覽頁顯示「找不到可匯入的成交紀錄」，不寫入任何資料。
- 圖片載入或辨識失敗：顯示錯誤訊息並回到首頁，不產生部分寫入。
- 辨識到融資、當沖、定期定額等不支援類型：該筆標為「不支援」，不可勾選，不中斷其他筆。
- 年份缺失（上行被截圖切掉）：該筆標為不完整，使用者補完日期才能匯入。
- 股數超出 1 到 32767 或價格不大於 0：該筆標為不完整；confirmImport 發現不合法項目時不寫入任何資料。

**Acceptance criteria:**

- TradeScreenshotParserTests：以兩張樣本截圖整理出的文字框資料（Vision 座標，原點在左下），驗證收合畫面解析出「元大台灣50 買 5 股 112.55 2026-09-30」與「華邦電 買 3 股 179.5 2026-10-01」；展開畫面解析出「台積電 買 1 股 2470.0 2026-09-22」與「瑞昱 賣 10 股 757.0 2026-09-23」；展開區塊文字與摘要列、表頭列不產生額外交易；「融資買進」列出現且 isSupportedType 為 false；頂部列被切掉的交易標為不完整且不借用其他列內容；合併的文字框（`09/30 盤中零股買進`）仍能解析。
- StockNameResolverTests（注入固定清單）：元大台灣50 對到 0050、華邦電對到 2344、台積電對到 2330、瑞昱對到 2379；名稱含空白的條目（例如 `元大MSCI A股`）與去除空白的 OCR 文字可以對上；不存在的股名回傳 nil；同名多筆回傳 nil。
- TradeImportViewModelTests：已存在相同的「股號、日期、價格、股數、買賣」時標為重複且預設不勾選；手動勾回後會被寫入；缺欄位的筆不可勾選；33000 股標為不完整且 saveNewRecord 不會被呼叫；手動輸入不存在於清單的股號仍不可勾選；confirmImport 只寫入勾選項目，且呼叫次數等於勾選筆數；同一天兩筆匯入紀錄的 date 不相等但仍是同一個台北日曆日。
- 手動驗證：在模擬器放入兩張樣本截圖，走完選圖、預覽、匯入，確認回到首頁後新股票立即出現在清單、買賣紀錄列表有對應項目，且 Firestore 有對應文件。

**Scope boundaries:**

- In scope：投資先生明細頁截圖、盤中零股與盤後零股的買進與賣出、預覽與去重、選擇要加入的清單、匯入後首頁與小工具更新、沿用既有寫入流程。
- Out of scope：其他券商、檔案匯入、手續費與稅的儲存、Core Data 與 Firestore schema 變更、把買賣紀錄綁定到清單、每檔股票分別選清單、股數單位換算（張與股）、自動辨識當沖等類型。

## Risks / Trade-offs

- [匯入的股票加入清單時，清單內出現重複股號（1.19 曾因此啟動崩潰）] → 底層 saveNewStockNumberToDB 已略過清單內既有股號，匯入層再先排除一次，並以 in-memory Core Data 測試匯入兩次後清單內股號不重複。
- [OCR 把數字認錯（例如 5 與 6、小數點，或多認一位數）] → 預覽頁必經且可編輯；股數與價格有範圍檢查；寫入前整批驗證。
- [投資先生改版，欄位位置或文字改變] → 解析器以文字錨點與相對座標而非固定位置，且有樣本單元測試；改版時新增樣本調整規則。
- [股名改名或清單未收錄，對不上股號] → 標紅並要求使用者手動輸入且驗證，不做模糊比對。
- [去重鍵把同日同價同股數的兩次合法交易判為重複] → 重複項只標記、預設不勾選，使用者可手動勾回。
- [截圖樣本只有盤中零股的買進與賣出] → 現股（整股）的股數欄是「股」還是「張」未確認，所以現股列一律標為「不支援」，不猜測單位；盤後零股的畫面文字未見過樣本，但零股的股數單位就是股；遇到不認得的類型也標為「不支援」。
- [同一張截圖重複匯入] → 去重鍵會把整批標為重複，預設不勾選。
- [不加入清單時，匯入紀錄在首頁看不到] → 預覽頁顯示提示，由使用者決定。

## Open Questions

- 已決定：現股（整股）的股數欄是以「股」還是「張」顯示無法確認（使用者平常只買零股，沒有現股樣本），所以第一版把現股列標為「不支援」。日後取得現股截圖並確認單位後，再另開變更加入。
