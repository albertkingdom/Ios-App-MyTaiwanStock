## 4. GitHub Actions Workflow 與 Secrets 設定

- [x] 4.1 在 `ios-signing` repo 新增一組唯讀 SSH deploy key，並在這個 repo 的 Settings → Secrets and variables → Actions 新增 `APP_STORE_CONNECT_API_KEY_ID`、`APP_STORE_CONNECT_API_ISSUER_ID`、`APP_STORE_CONNECT_API_KEY_CONTENT`、`MATCH_GIT_PRIVATE_KEY`、`MATCH_PASSWORD` 五個 Secrets，對應設計決策「`MATCH_GIT_PRIVATE_KEY`：對 `ios-signing` repo 唯讀的 SSH deploy key 私鑰」，實現規格「App Store Connect authentication via API key only」與「Signing without local Apple ID interaction」。驗證方式：`ios-signing` repo 的 Deploy keys 列表可見一組唯讀（Read-only）的 key；GitHub repo 的 Secrets 列表可見這五個名稱（值本身不可見，僅確認名稱存在且非空）。
- [x] 4.2 新增 `.github/workflows/testflight.yml`，設定 `name: TestFlight Release`、`on.workflow_dispatch:` 與 `on.push.tags: ['v*']`、`jobs.release.runs-on: macos-latest`，實現規格「Manual TestFlight release trigger」中「Pushing a version tag triggers a release automatically」與「Pushing to a branch does not trigger a release」情境，對應設計決策「Workflow 觸發方式：`workflow_dispatch`（手動觸發）與 `v*` git tag push（自動觸發）並存，不綁定固定分支的 push」。驗證方式：檢視 YAML，`on` 區塊同時包含 `workflow_dispatch` 與 `push.tags: ['v*']`，且沒有 `branches` 相關的 `push` 觸發條件；本機或測試分支上 push 一個不含 `v*` 前綴的一般 commit 不會觸發 workflow，push 一個 `v*` tag 才會觸發。
- [x] 4.3 在 workflow 中新增 checkout、`webfactory/ssh-agent@v0.9.0`（載入 `MATCH_GIT_PRIVATE_KEY`）、`ssh-keyscan github.com` 信任 host key、SPM resolve、安裝 fastlane、執行 `bundle exec fastlane ios beta` 的 steps，並把 4.1 建立的五個 Secrets 對應注入為環境變數（`APP_STORE_CONNECT_API_KEY_ID`、`APP_STORE_CONNECT_API_ISSUER_ID`、`APP_STORE_CONNECT_API_KEY_CONTENT`、`MATCH_GIT_PRIVATE_KEY`、`MATCH_PASSWORD`），對應設計決策中 `webfactory/ssh-agent` 的做法（沿用 `ios-mybusapp` 既有模式），實現規格「Archive, export, and upload to TestFlight」與「Failures are surfaced without partial-success states」。驗證方式：檢視 YAML，`ssh-agent` step 正確載入 `secrets.MATCH_GIT_PRIVATE_KEY`，`fastlane` 執行 step 的 `env` 區塊包含其餘四個環境變數，且各自對應到 `secrets.<NAME>`。
- [x] 4.4 在 checkout 之後、其餘步驟之前新增一個 step，僅在 `github.event_name == 'push'`（tag 觸發）時執行：`git fetch origin release` 後跑 `git merge-base --is-ancestor "$GITHUB_SHA" origin/release`，非 0 結束碼時輸出明確錯誤訊息並讓 job 失敗；`workflow_dispatch` 觸發時跳過此 step，實現規格「Tag-triggered releases must originate from the release branch」的三個情境，對應設計決策「tag push 觸發時，限定 tag 必須指向 `release` 分支歷史中的 commit」。驗證方式：檢視 YAML，此 step 有 `if: github.event_name == 'push'` 條件，且指令使用 `git merge-base --is-ancestor`。
